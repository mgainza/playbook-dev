⚡ Frontend Architecture Decision Playbook

Guía universal de decisiones para construir componentes limpios, desacoplados y mantenibles.

🚦 Árbol de Decisión: Antes de crear un componente

1. ¿El componente calcula cosas, valida inputs, consulta APIs o tiene >1 useEffect?

SI ➔ Extraer a Custom Hook (useXxx)

El componente JSX solo debe consumir el "DTO" devuelto por el hook. No mezcles reglas de negocio con el árbol visual.

2. ¿El contenedor visual es idéntico pero lo que va adentro cambia según la plataforma o contexto?

SI ➔ Aplicar Pattern Slot (children)

En lugar de meter if/else dentro de la vista, crea la estructura contenedora y delega el contenido interior mediante children.

3. ¿El componente usa dependencias que NO existen en todas las plataformas (ej: Web vs Native)?

SI ➔ Separación por archivo de plataforma (Component.tsx + Component.web.tsx)

NUNCA uses Platform.OS === 'web' ? <Web/> : <Native/> en un mismo archivo si hay imports nativos incompatibles. El bundler debe descartar el archivo completo.

4. ¿El componente se usará en más de un lugar con ligeras diferencias de layout?

SI ➔ Pasar de estado interno a Componente Controlado

Saca los useState locales y recibe value y onChange desde las props. Quien invoca el componente es el dueño de la verdad.
