Frontend Architecture & React Native / Web Playbook

Guía práctica de patrones de diseño, separación de responsabilidades y compatibilidad multiplataforma.

1. Separación Lógica vs. Vista (Custom Hooks)

Arquitectura

Aplica el principio de Responsabilidad Única (SRP) dividiendo el componente en dos capas:

  • Custom Hook (useXxx): Maneja estados (useState), efectos (useEffect), validaciones, formateos y llamadas a API. Es la capa de dominio/servicio.
  • Componente UI (XxxField / XxxView): Recibe un DTO de props y retorne JSX. No calcula reglas de negocio ni maneja lógica asíncrona.
Regla de oro: Si tiene hooks complejos o lógica condicional de negocio, extraelo a un custom hook. Facilita los Unit Tests sin necesidad de renderizar UI.

2. Extensión Web vs. Native (.web.tsx)

Multiplataforma

Evita romper builds en Web por importaciones de módulos nativos incompilables (ej. @react-native-community/datetimepicker):

  • NUNCA uses ternarios binarios: Platform.OS === 'web' ? <Web /> : <Native /> en el mismo archivo. La importación nativa igual entrará al bundle web y fallará al inicializar.
  • Aprovecha el bundler (Metro/Webpack): Separa en Component.tsx (Nativo) y Component.web.tsx (Web). El bundler descartará la rama no utilizada.

3. Inversión de Control con Slots (children)

Patrones UI

Usa la prop children para inyectar comportamiento específico en contenedores compartidos:

  • Cuando el layout visual (labels, bordes, errores) sea idéntico pero la interacción interna cambie según plataforma o contexto.
  • Permite que el componente presentacional no sepa qué selector o entrada se está usando internamente.
<DateField {...props}>
  {/* El slot inyecta el control adecuado */}
  {isWeb ? <input type="date" /> : <DateTimePicker />}
</DateField>

4. Manejo Seguro de Modulos Desconocidos / Null Checks

Debugging

Causa común del error "Element type is invalid: expected a string/class but got: object/undefined":

  • Causa 1: Módulo nativo no soportado en web importado globalmente.
  • Causa 2: Mezcla entre export default y export const (named import).
  • Causa 3: Dependencia circular causada por re-exportar desde archivos de índice (barrel files).
Solución: Importa siempre por ruta directa (ej. ../InputWrapper) dentro de la misma carpeta de componentes para evitar dependencias circulares.

5. Estructura de Archivos Recomendada (3 Capas)

Estructura

Patrón multiescena para componentes complejos de formulario o UI avanzada:

components/date-picker/
├── useDateField.ts      --> Lógica pura (Estado de UI, hooks y reglas)
├── DateField.tsx        --> Presentación pura (Labels, bordes, wrapper, mensaje de error)
├── DatePicker.tsx       --> Integración Nativa (iOS / Android)
└── DatePicker.web.tsx   --> Integración Web (HTML5 nativo u omisión de librerías móviles)
